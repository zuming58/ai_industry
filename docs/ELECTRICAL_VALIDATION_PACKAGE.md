# FX5U 集中电气验证包

## 目的与安排

日常开发不要求用户或电气工程师持续介入。Agent 先完成能够通过代码、规则、自动化测试、隔离仿真和审计验证的工作；只有必须依赖黄金工程、厂商软件、真实接线或专业控制判断的事项集中到本验证包。

建议一次安排连续 1–2 天。所有结果必须填写实际值并保存证据；“未执行”不能记为通过。

## 进入条件

- 自动化门禁全绿，当前 Commit 和生成器版本已记录；
- 一套已脱敏的小型完成项目：1–2 轴、2–4 气缸、20–60 点 I/O，避开机器人、视觉和安全 PLC；
- 原机电对接表、I/O 表、动作/节拍表、最终 PLC 工程和已知验收结果；
- 与项目一致的 GX Works3、GX Simulator3、MX Component 版本和合法授权；
- FX5U CPU、必要 I/O/通信模块、24 VDC 电源、断路/急停、端子、指示灯或安全的负载模拟器；
- 电气工程师、受控测试台和断电/回退权限。

## 禁止事项

- 不连接生产设备做首次试验；
- 不由 Agent 执行 PLC 下载、RUN/STOP 或强制输出；
- 不把安全 PLC、急停、门锁、光栅等逻辑纳入自动生成；
- 不在未核对模块、地址、电源和负载前上电；
- 任何 PLC 操作均由电气工程师在厂商工具中执行并确认目标。

## 证据与回退

验证材料放在不进 Git 的 .private/validation/<date>/，按 environment、golden-import、compile、simulation、hardware 和 signoff 分类。每项至少记录项目 ID、MachineSpec revision/hash、Program Commit、生成器版本、厂商软件版本、PLC 与模块信息、操作者、时间、结果和原始日志路径。

1. 任一目标、版本或接线不一致时停止，不尝试猜测修复。
2. 编译与模拟失败保留原日志和工程副本，创建 Issue 与新分支，不覆盖生成基线。
3. 硬件异常立即由电气工程师进入安全状态、断开能量并按现场规程处理。
4. 每个验证发现转成最小复现夹具和自动化回归测试；只有无法自动化的专业判断继续保留人工门。

## 通过定义

- M1 最终验收：G01–G04 通过且差异已回归测试覆盖。
- 厂商工具验证：V01–V04、S01–S04 按精确版本通过。
- 硬件实测：H01–H05 在明确台架配置通过。
- 电气工程师确认：普通控制、互锁、异常、复位和失效状态有签名记录。

这些等级相互独立；模拟通过不能替代硬件实测，普通控制确认不能替代机械安全评估。
