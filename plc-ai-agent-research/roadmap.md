# Delivery Roadmap and Decision Gates

## 1. 总体路线

不要先开发“万能 PLC Agent”，也不要先买边缘盒。正确顺序是：真实样本 → 厂商适配器技术验证 → MachineSpec → 确定性代码与测试 → 厂商仿真闭环 → 离线诊断 → 只读现场采集 → 企业私有化。

建议以一个小型、已交付、可脱敏的工站为黄金样本。理想范围：1–2 个伺服、2–4 个气缸、20–60 点 I/O，有自动/手动/复位、5–15 个动作步骤、3–8 个典型报警；首个样本不含机器人、安全 PLC 和复杂视觉。

## 2. Phase 0：证据与适配器技术验证（2 周）

### 2.1 输入

- 用户和电气伙伴提供黄金项目的机电对接表、I/O、程序、报警和验收资料；
- 安装并记录 AutoShop、GX Works3、模拟器、库和授权的精确版本；
- 建立脱敏规则，不把客户名称、配方、图纸和现场地址上传公网模型。

### 2.2 AutoShop 十项门槛

在隔离电脑和副本工程上验证：

1. 能否稳定读取项目、POU、变量、设备和版本信息；
2. 能否创建或修改一个 ST POU，并无损回读；
3. 重复导入/导出是否保持地址、注释、中文、库引用和工程结构；
4. 能否触发完整编译并结构化获得错误位置和消息；
5. 能否启动模拟环境，或至少连接受控测试 PLC；
6. 能否自动写入测试输入并读取输出/内部状态；
7. 定时器、上升沿、保持变量、掉电重启和扫描周期行为是否可验证；
8. 汇川运动功能块、轴配置和 EtherCAT 配置可自动化到什么程度；
9. 失败后能否回滚到原工程，是否有自动保存、无撤销等危险行为；
10. 厂商 EULA、第三方项目许可证、预编译代理来源和商业再分发是否允许。

### 2.3 决策门

- **Go-A**：1–7 全部通过，8 的范围足以覆盖黄金项目，9–10 无红线；以 AutoShop 为首适配器。
- **Go-B**：代码导入需人工操作，但编译/模拟/变量读写稳定；保留人工导入门，继续做半自动 MVP。
- **Stop/Redirect**：编译诊断不可可靠获取、工程往返破坏数据、版本极脆弱或许可不可接受；转三菱闭环，汇川保留人工导出。

### 2.4 三菱备用验证

同步用一个 FX5U 小项目验证 GX Works3 编译、GX Simulator3 运行和 MX Component 对模拟变量的读写。核心是证明测试驱动可重复；代码导入自动化若无官方接口，可以暂时人工完成。

### 2.5 完成定义

提交适配器能力矩阵、20 次重复运行结果、失败录像/日志、许可证记录，以及明确的首平台决策。没有这份结果，不进入大规模 UI 或 Agent 开发。

## 3. Phase 1：MachineSpec 与确定性生成核心（4–6 周）

### 3.1 功能

- Excel 模板与 Web 向导导入；
- Project、Components、Signals、Hardware、Sequences、Interlocks、Alarms、ParametersAndTiming、AcceptanceTests 九张表；
- JSON Schema、版本迁移和工程一致性检查；
- 气缸、伺服基础轴、变频器、工站状态机、模式管理和报警管理模板；
- 生成 ST、变量/I/O 表、报警表、流程图、追踪矩阵和测试定义；
- 工程师逐项确认 LLM 提出的结构化补全。

### 3.2 质量门

- 黄金项目所有 I/O、步骤、互锁、报警和验收项可追踪；
- 同一输入重复生成的确定性部分完全一致；
- 人为制造的断引用、冲突输出、无超时、不可达步骤和单位错误都能被发现；
- 核心模板达到单元测试和代码审查要求；
- 安全相关字段被隔离，不能进入普通控制模板。

## 4. Phase 2：厂商编译—仿真—报告闭环（4–6 周）

### 4.1 功能

- 首平台适配器导入/应用生成物；
- 编译诊断解析和最小补丁流程；
- 模拟器驱动、变量采样和时序断言；
- 正常流程、超时、传感器卡住、互斥冲突、复位和重启测试；
- 变异测试证明测试集能发现条件颠倒和互锁删除；
- 生成带工具版本、工程哈希、规格哈希和结果证据的报告；
- 电气工程师批准/拒绝/要求修改。

### 4.2 MVP 验收指标

建议先设工程指标，不设“自动写完率”这样的虚荣指标：

- 规格完整性检查对预埋缺陷召回率 ≥ 90%；
- 黄金项目的正常与已知异常测试通过率 100%；
- 生成后人工修改量按行/块记录，目标逐版本下降；
- 编译错误修复不得引入回归；
- 同一版本环境连续 20 次流水线执行无随机失败；
- 每个产物都能追溯到需求、模板、工具和审批人；
- 从导入规格到首轮仿真报告的工程时间相对人工基线明显下降，具体目标由实测基线确定。

## 5. Phase 3：离线故障诊断 MVP（约 4 周）

### 5.1 范围

- 导入报警历史、变量 CSV/Trace、人工现象和最近变更；
- 按设备型号与版本检索手册；
- 使用 MachineSpec 判断当前步骤需要哪些命令、反馈和互锁；
- 输出证据、候选原因、区分性检查和人工确认项；
- 对一个离线代码分支生成可选补丁与回归测试，不接现场下载。

### 5.2 数据集

至少整理 30–50 个真实或高保真故障案例。每例包含实际根因、错误候选、有效检查、无效检查、修复动作和验证结果。没有这组标注，不能可靠评价诊断能力。

### 5.3 指标

- 手册引用准确率；
- Top-3 候选是否覆盖真实根因；
- 第一条验证动作能否有效区分候选；
- 缺证据时是否正确拒绝下结论；
- 高风险建议拦截率；
- 工程师从报警到定位的时间变化。

## 6. Phase 4：只读现场试点与私有化（8–12 周）

### 6.1 先软件、后硬件

第一批现场可使用已有工控机/边缘计算机，不急于自研硬件。先验证：

- OPC UA/Modbus/厂商协议中哪些变量可只读获得；
- 时间同步、断线缓存和数据量；
- OT 网络白名单、账户权限和审计；
- 设备版本与数据标签是否始终一致；
- 工程师是否愿意使用诊断证据包。

数据与流程稳定后，再定义自有小盒的工业温度、电源、双网口、隔离、存储、TPM/安全启动、维修和认证要求。

### 6.2 推理部署

- 车间盒：协议采集、缓存、规则和轻量界面；
- 内网工作站/服务器：RAG、代码模型和复杂推理；
- 调试笔记本：可选离线演示与单机服务；
- 模型选型：用本项目任务集比较准确率、延迟、显存、并发和中文/PLC 能力，不预先承诺某个参数规模。

## 7. 6–12 个月产品化方向

1. 验证过的机构功能块与测试包市场/企业库；
2. 第二厂商适配器与差异报告；
3. AutomationML/PLCopen XML 的导入导出映射；
4. 电气 BOM、I/O 分配和 EPLAN/ECAD 交换，但需另做接口调研；
5. 调试数据自动回填 MachineSpec 与故障案例；
6. 设备族模板、客户标准和程序风格规则；
7. 经过安全评估的有限在线参数建议，仍保留工程师批准；
8. 与机械计算选型平台共享元件、参数、机构和节拍数据。

## 8. 立即可执行的下一步

1. 用户与电气伙伴选定黄金项目并脱敏；
2. 把现有机电对接表按 `machine-specification.md` 九张表做一次映射；
3. 确认 AutoShop/H5U 的确切软件、CPU、固件、运动库和许可版本；
4. 在隔离电脑执行十项 AutoShop 技术验证；
5. 同时建立三菱模拟闭环备用样本；
6. 用结果决定首个适配器，不再凭印象争论“汇川还是三菱更简单”。
