# 🎯 老王 PLC AI Agent 产品 · 三大方向完整方案

> **> 产品 愿景**：打造一个一个"工业 PLC AI 助手"工具——三个方向集成到一个 Agent 里：
>
> 1. **方向 A**：AI 盒子（边缘数据分析 + 故障诊断 Agent）
> 2. **方向 B**：AI 写程序（自然 → PLC 代码 + 编译验证）
> 3. **方向 C**：AI 调试 AutoShop（合伙人电气工程师用的 IDE 增强）
>
> **目标**：交给 Codex 开发，老王 + 合伙人 两个人就能用起来。

## 二、方向 A · AI 盒子（边缘数据分析 + 故障诊断）

### 2.1 目标

让老王能做出一个硬件小盒子：
- 插到 PLC 旁边 → 自动采集数据
- 数据不出厂（私有化）
- AI 自动分析 + 故障诊断
- 微信/钉钉推送报警

### 2.2 技术栈（Codex 需要开发的模块）

#### 模块 A1：硬件抽象层

```yaml
硬件选择:
  推荐: Jetson Orin NX 16GB（国产方案用 RK3588）
  接口:
    - 4×RJ45（PLC/MES/上位机/调试）
    - 2×USB 3.0
    - 1×RS485（Modbus RTU 备用）
    - 1×HDMI（本地显示）
  
  电源: 24V DC 工业宽压
  散热: 无风扇被动散热
  防护: 工业铝合金，宽温 -20~70°C
  
  来源（采购）:
    - 主力: Jetson Orin NX 16GB（¥15,000）
    - 国产备选: 赋创 FR50（¥20,000-30,000）
```

#### 模块 A2：协议采集层

```yaml
框架选择:
  核心: EMQX Neuron（已开源，ARM64 原生支持）
  
协议支持（按优先级）:
  P0 主协议:
    - Modbus TCP/RTU（汇川/三菱/西门子都支持）
    - OPC UA（西门子主推）
    - S7 协议（西门子专有）
    - Profinet/EtherCAT（西门子/倍福）
    
  P1 辅助协议:
    - DL/T645（电表）
    - IEC104（电力）
    - MQTT（IoT 设备）
    - HTTP API（向上接入 MES）
    
  开发工作量: 协议适配器已由 Neuron 提供，配置即可
```

#### 模块 A3：数据存储层

```yaml
时序数据: TDengine 3.0+
  性能: 单机 100万 点/秒
  压缩: 10-20x
  集成: 与 Neuron 直接对接
  
关系数据: PostgreSQL 16
  用途: 设备元数据、报警代码库、用户配置
  
缓存: Redis（可选）
  用途: 实时数据缓存 + 会话管理
  
数据保留策略:
  原始: 30 天
  聚合: 1 年
  知识库: 永久
```

#### 模块 A4：AI 推理层

```yaml
模型部署:
  框架: Ollama（一行命令启动）
  
模型选择（按场景）:
  轻量推理: DeepSeek-R1-Distill-Qwen-1.5B（INT4，~1GB）
  通用推理: DeepSeek-R1-Distill-Qwen-7B（INT4，~5GB）
  复杂推理: DeepSeek-R1-Distill-Qwen-14B（INT4，~10GB）
  
推理框架:
  简单任务: Ollama API
  高并发: vLLM
  
向量库: Chroma（小规模）→ Milvus（生产）
Embedding: BGE-large-zh-v1.5（中文最优）
```

#### 模块 A5：故障诊断 Agent

```yaml
诊断 Agent 架构（关键！）：
  输入层: 多源证据包
    - PLC 诊断缓冲区（西门子/汇川/三菱）
    - 伺服报警寄存器（Profinet/EtherCAT 通讯读取）
    - 传感器原始信号（振动/温度/电流）
    - HMI/SCADA 操作记录
    
  证据门（关键！不是信号就是故障）:
    - 通信有效？
    - 时间戳新鲜？
    - 序列号连续？
    - 传感器自检？
    - 配置版本一致？
    
  状态机: 当前工艺阶段 + 预期信号
  
  推理层: 多智能体协同
    - 通信层 Agent
    - 物理层 Agent
    - 业务层 Agent
    - 决策层 Agent
    
  输出: 故障代码 + 原因 + 药方 + 风险等级 + 处置建议
```

#### 模块 A6：知识库 RAG

```yaml
框架: FastMe RAG（制造业专属）
  
知识库内容:
  - 汇川报警代码手册（E.001-E.999）
  - 西门子诊断缓冲区说明
  - 三菱报警代码
  - 老师傅维修经验 PDF
  - 客户历史故障库
  
文档拆解器（FastMe 内置）:
  - log: 故障日志、运行日志
  - manual: 操作手册、维修手册
  - business: 工单、质检单
  - sop: 作业指导书、BOM、工艺流程
  
场景路由:
  - fault_diagnosis: 故障诊断
  - manual_query: 手册查询
  - work_order_trace: 工单追溯
  - default: 默认问答
```

#### 模块 A7：推送与告警

```yaml
推送通道:
  微信: 企业微信机器人 webhook（推荐）
  钉钉: 钉钉机器人 webhook
  飞书: 飞书机器人 webhook
  SMS: 阿里云短信 / 腾讯云短信（备用）
  
告警等级:
  P0: 紧急停机 → 立即推送 + 电话
  P1: 严重故障 → 立即推送
  P2: 一般异常 → 5 分钟内推送
  P3: 提示信息 → 汇总日报
```

## 三、方向 B · AI 写程序（自然语言 → PLC 代码）

### 3.1 目标

老王想做的是：
- 自然语言描述设备工艺 → AI 生成 PLC 代码
- 代码可以直接导入 AutoShop（汇川）/ TIA Portal（西门子）/ CODESYS
- AI 生成的代码自动编译检查 → 通过率 > 80%
- 老王 + 合伙人用得上

### 3.2 技术栈（Codex 需要开发的模块）

#### 模块 B1：自然语言理解层

```yaml
输入:
  - 自然语言工艺描述
  - 流程图（PNG/JPG/PDF）
  - I/O 分配表（CSV/Excel）
  - 设备清单（文本/表格）
  - 历史程序（梯形图/ST 代码参考）

LLM 选择:
  推荐: DeepSeek-V3 / Qwen2.5-72B（代码能力强）
  备选: GPT-4o / Claude 3.5（如果预算充足）

提示词工程:
  - 角色: 你是 PLC 编程专家
  - 上下文: PLC 型号 + 工艺要求 + 编程规范
  - 输出格式: ST/SCL/梯形图代码 + 注释
  - 约束: 符合 IEC 61131-3 / 西门子 SCL 规范
```

#### 模块 B2：代码生成层

```yaml
支持编程语言（按优先级）:
  P0（汇川，老王主要客户）:
    - AutoShop ST 语言
    - AutoShop 梯形图（LD）
    - AutoShop SFC（顺序功能图）
    
  P1（西门子，复旦/西门子客户）:
    - TIA Portal SCL
    - TIA Portal LAD（梯形图）
    - TIA Portal FBD
    
  P2（CODESYS，国产部分品牌）:
    - CODESYS ST
    - CODESYS CFC

代码模板库:
  框架: FastMe RAG（复用）
  内容:
    - 常见工艺模板（气缸控制、伺服控制、PID）
    - 标准库函数（汇川/西门子/三菱）
    - I/O 分配示例
    - 历史优秀程序
```

#### 模块 B3：编译验证层（关键！）

```yaml
汇川 AutoShop 集成:
  API: AutoShop 提供 COM 接口（待调研）
  方式:
    1. AI 生成 ST 代码 → 保存为 .st 文件
    2. 调用 AutoShop 命令行编译
    3. 解析编译错误 → 反馈给 AI
    4. AI 修复 → 重新编译 → 循环
  
  关键工具: AutoShop CLI / 脚本接口（Codex需研究）
  
西门子 TIA Portal 集成:
  API: TIA Openness（已开放，需授权）
  参考: RealPLC TIA Agent 已实现完整闭环
  
  关键工具: TIA Openness API（C#） + Python 包装

CODESYS 集成:
  API: CODESYS Scripting Engine
  参考: RealPLC CODESYS 已集成（无需费用）
  
  关键工具: CODESYS IDE 脚本 + Python 包装
```

#### 模块 B4：质量检查层

```yaml
代码审查 Agent（plc-functional-verifier）:
  来源: GitHub Copilot 多智能体测试
  
  工具: 只读分析模式
  检查项:
    - 状态机切换边界
    - 顺控联锁 Permissives/Inhibits
    - HSC 计数器边界
    - 掉电恢复逻辑
    - NVRAM 数据完整性
    - 安全互锁
    - 急停逻辑
  
  输出: 审查报告 + 风险点 + 修复建议
```

#### 模块 B5：双向转换层

```yaml
ST ↔ 梯形图 互转:
  参考: 汇川已实现一键互转
  
  应用:
    - 老客户老程序（梯形图）→ AI 学习转 ST
    - AI 生成 ST → 工程师查看梯形图
    - 国产/进口 PLC 程序迁移
```

### 3.3 工作流

```
输入：自然语言工艺需求
   ↓
模块 B1：解析（LLM）
   ↓
模块 B2：生成代码（LLM + 模板库）
   ↓
保存为 .st 文件
   ↓
模块 B3：调用 AutoShop 编译
   ↓
   ├── 编译通过 → 模块 B4：质量审查
   │                ↓
   │              输出代码包
   │
   └── 编译失败 → AI 修复 → 重新编译
                  ↓
                  最多 3 轮循环
                  ↓
                  还失败 → 人工介入
```

### 3.5 Codex 开发建议

```
优先级:
  P0: 汇川 AutoShop ST 代码生成 + 编译验证
  P1: 西门子 TIA SCL 代码生成 + 编译验证（参考 RealPLC）
```

## 四、方向 C · AI 调试 AutoShop（合伙人电气工程师用）

### 4.1 目标

让老王的合伙人（电气工程师）能用得上：
- 在 AutoShop IDE 里调用 AI 助手
- AI 帮看代码、找 bug、优化
- 自然语言对话调试 PLC 程序
- 自动测试和验证

### 4.2 技术栈

#### 模块 C1：IDE 集成

```yaml
AutoShop（汇川）集成:
  方式 1（推荐）: LSP 协议（Language Server Protocol）
    - 汇川 AutoShop 可能支持 LSP
    - 老王合伙人可以验证
    
  方式 2: AutoShop 插件 SDK
    - 汇川可能有 COM/.NET 插件接口
    - 需要 Codex 调研
    
  方式 3: 独立 Web IDE
    - 我们的 Web 应用 + AutoShop 联动
    - 类似 VS Code + Continue
    
  备选 IDE 集成:
  TIA Portal: TIA Openness API（RealPLC 已实现）
  CODESYS: Scripting Engine（RealPLC 已实现）
```

#### 模块 C2：代码辅助层

```yaml
代码补全:
  - 基于上下文的代码补全
  - 基于历史项目风格的补全
  - 库函数自动提示

代码审查:
  - plc-functional-verifier 智能体（参考无敌金金霸王）
  - 静默运行，不打断工程师

代码解释:
  - 选中代码 → AI 解释
  - 自然语言问答："这段代码什么意思？"
  - 中文友好
```

#### 模块 C3：调试助手

```yaml
在线调试:
  - PLC 实时状态查询
  - 变量值监控
  - 报警历史查看
  
离线调试:
  - 仿真运行（PLCSIM 类似）
  - 单步执行
  - 断点管理
  
知识库问答:
  - "FX-5U 的 HSC 怎么用？"
  - "Modbus 通讯失败怎么排查？"
  - "PID 参数怎么调？"
```

#### 模块 C4：测试自动化

```yaml
单元测试:
  - 自动生成测试用例
  - 验证边界条件
  - 覆盖率报告

集成测试:
  - 多 PLC 协同测试
  - 通讯协议测试
  - 报警流程测试
```
