## 一、为什么需要硬件盒子

### 老王的判断完全正确

> "工厂里它这个信息不能外传的嘛，最好是能做成硬件的小盒，插到设备上读取这个资料什么的。"

### 三大核心原因

| 原因 | 表现 |
|------|------|
| **数据安全** | 工厂数据（工艺/配方/参数）不能出网 |
| **网络不稳定** | 工厂网络经常掉线、断网 |
| **响应延迟** | 高速控制需要毫秒级响应，云端往返来不及 |

### 数据出网 vs 不出网对比

| 方案 | 数据安全 | 部署成本 | 维护成本 |
|------|---------|---------|---------|
| **云端 AI** | ❌ 数据出网 | 低（按量付费）| 中 |
| **私有化服务器** | ✅ 数据不出厂 | 高（10-20万）| 中 |
| **AI BOX（边缘）**| ✅ 数据不出厂 | 中（2-5万）| 低 |

## 二、AI BOX 的四大核心能力

## 六、AI BOX 与 PLC 的连接方式

### 方式 1：Profinet 镜像（推荐 · 无侵入）

```
客户网络（生产）：
[PLC] ←Profinet→ [远程 I/O]

AI BOX 通过镜像端口监听：
[AI BOX] ←Profinet Mirror→ [Switch 镜像口]

✅ 优点：
- 零侵入，PLC 程序不变
- 不影响实时性
- 主流 PLC 都支持

⚠️ 限制：
- 需要交换机支持镜像
- 部分老 PLC 不支持
```

### 方式 2：Modbus TCP 主动读（最简单）

```
[AI BOX] --Modbus TCP 读寄存器--> [PLC]

✅ 优点：
- 配置简单
- 几乎所有 PLC 都支持
- 老 PLC 也能用

⚠️ 限制：
- 数据延迟（取决于扫描周期）
- 数据维度有限
```

### 方式 3：OPC UA 订阅（最先进）

```
[AI BOX] --OPC UA 订阅--> [PLC OPC UA Server]

✅ 优点：
- 数据语义丰富
- 实时性好
- 支持历史数据

⚠️ 限制：
- 需 PLC 支持 OPC UA
- 配置稍复杂
```

### 方式 4：西门子 S7 协议（西门子专有）

```
[AI BOX] --S7 Communication--> [S7-1200/1500]

✅ 优点：
- 直接读取西门子 DB 块
- 高效
- 不需要额外授权

⚠️ 限制：
- 仅限西门子 PLC
```

## 七、AI BOX 的 7 大场景应用

### 场景 1：实时故障诊断

```
触发：PLC 报警
AI BOX：
1. 读取诊断缓冲区
2. 读取伺服报警代码
3. 查询本地 RAG 知识库
4. 输出诊断结论 + 推荐处置
5. 推送微信/钉钉

时效：< 3 秒
```

### 场景 2：老师傅知识数字化

```
第一次部署：
1. 老师傅口述典型故障处理过程
2. AI 转化为结构化规则库
3. 存入本地知识库

后续运行：
1. 设备出现类似故障
2. AI 自动匹配历史经验
3. 输出处理建议
```

### 场景 3：预测性维护

```
数据采集：
- 振动（加速度传感器）
- 温度（热电偶）
- 电流（互感器）

AI 模型：
- LSTM 时序预测
- 异常检测

输出：
- "主轴 7 天内可能故障，建议检修"
```

### 场景 4：参数自适应调整

```
场景：客户换了批物料（电芯厚度变了 0.3mm）
AI BOX：
1. 检测到异常参数
2. 推理新参数
3. 输出建议（不直接修改 PLC）
4. 工程师确认后写入
```

### 场景 5：自然语言查询设备状态

```
客户问："5 号车床今天效率怎么样？"

AI BOX：
1. 查询设备数据
2. 检索知识库
3. 生成回答

输出：
"5 号车床今日运行 8 小时，加工 320 件，
OEE 85%，比昨日提升 5%。
无报警。设备状态良好。"
```

### 场景 6：自动化工单

```
场景：设备出现故障
AI BOX：
1. 识别故障类型
2. 自动创建维护工单
3. 推送维修人员
4. 维修完成后自动更新知识库
```

### 场景 7：远程运维

```
客户在苏州，工程师在上海
AI BOX：
1. 设备数据实时同步
2. AI 自动诊断
3. 工程师远程查看 + 远程指导
```
