## 二、关键技术事实（决定技术路线）

1. **AI 写 ST（结构化文本）远比梯形图准**——ST是文本、梯形图是图形，LLM处理文本天然强
2. **技术路线定为：AI 生成 ST → 软件一键转梯形图**（汇川工具已支持互转，92%准确率）
3. **MCP 是这波爆发的转折点**——以前 AI 是"蒙着眼睛凭空写"，现在通过 MCP 能读工程里的变量、DB块、库，生成的是能直接编译的代码
4. 编程闭环不是在聊天窗口里生成，而是**进真实工程编译验证，错误回传，AI自动修复，人只做最后确认**

## 三、让 AI 写 PLC 程序，需要事先输入哪些条件

1. **IO 表**——输入输出口定义（做方案时本来就要出）
2. **设备/模块清单**——几个轴、伺服型号、气缸传感器（= BOM表内容）
3. **工艺时序/动作流程**——"先夹紧→确认到位→伺服进给→保压→退回"，自然语言描述即可
4. **安全联锁要求**——急停、门禁、防撞逻辑
5. **已有代码模板/库**（可选）——过去项目的标准块

**关键洞察：前四样做非标方案时本来就要出（设备清单=BOM、动作时序=方案书内容），设计流程和AI编程输入天然重合——这是老王比纯软件团队强的地方。**

## 四、汇川入局：坏消息也是好消息

坏消息：你想到的朱兴明也想到了，iFG平台、PLC代码生成、伺服预测性维护全在推，中天钢铁灯塔工厂已落地。

好消息（机会窗口）：
1. **汇川做的是通用能力，不做垂直行业**——非标设备行业的工艺知识库它没有（动力总成拧紧站的标准时序、电芯堆叠站的安全联锁，这些在老王脑子里）
2. **汇川 AutoShop/InoProShop 的第三方 MCP 生态是空的**——AM 系列 PLC 的 InoProShop 就是 CODESYS 内核换皮，理论上能接标准 CODESYS MCP Server，但没人给非标行业做垂直 Agent
3. 汇川自己披露的数据反过来验证市场：92%准确率、调试省77%——**客户教育已有人做**

**定位：不做汇川竞品，站在汇川生态上做垂直行业层——跟现在"做非标设计、不跟设备厂竞争"同一个逻辑。**

## 六、编程闭环流程（行业已跑通）

```
前置输入（IO表+设备清单+工艺时序+安全联锁）
   ↓
Agent 生成 ST 代码
   ↓
导入真实 PLC 编程软件（InoProShop / TIA）
   ↓
编译验证
   ↓ 错误
错误回传 → AI 自动修复 →（循环直到编译通过）
   ↓ 通过
工程师确认 → 下载调试
```
