# 调研：PLC 故障诊断 AI 方案（2026-08-26）

> 老王核心疑问："PLC本身程序错误能分析吗？连接的伺服驱动器报错，PLC能知道吗？"——**能，而且不需要额外接线。**

## 一、伺服报错 PLC 能感知的机制（技术基础）

EtherCAT 总线 + CiA402 行规下，汇川 SV660N 这类总线伺服，故障信息全走总线报文，PLC 侧直接读对象字典两个寄存器：

- **0x6041 状态字**——状态机在哪一步、有没有故障位
- **0x603F 故障码寄存器**——具体故障号（Er.xxx 格式）

也就是说：**伺服一报错，故障码毫秒级就在 PLC 数据区里了**。现在现场的流程是：工程师看 HMI 报警文本 → 翻手册 → 查故障码含义 → 按故障树排查——这中间全是人工环节，全是 Agent 可以吃掉的空间。

汇川伺服还有黑匣子功能：故障/警告分级记录 10-20 组历史。

## 二、汇川伺服常见故障码（知识库骨架）

- ER.b00 位置偏差过大
- ER.E08 EtherCAT 同步丢失
- ER.E15 同步周期误差过大
- 回零失败
- 数据溢出
- EtherCAT 掉站

**现成RAG素材：汇川官方《AM600+IS620N 常见故障处理指导》PDF**——整本就是故障树排查文档，含故障码含义+原因+排查步骤，直接喂知识库，不用自己攒。

## 三、标杆案例（都跑通了）

| 案例 | 机制 |
|------|------|
| **CODESYS AI 诊断工作流**（Dan Buda, LinkedIn 实测） | PLC报警 → HTTP webhook 触发 → AI agent 经 MCP 读 PLC 实时值 → MQTT通知。输出不是复读报警，而是"故障输入激活，PLC正确锁存电机故障，先查驱动器/过载/启动器"这种带定位的结论 |

## 四、诊断 Agent 技术栈（第一步纯软件，参赛 demo）

```
知识库：汇川故障手册PDF + 故障案例 + 自己的调试记录（RAG）
   ↓
诊断 Agent：DeepSeek API + Function Calling
   工具1：read_fault_code() —— 解析 Er.xxx 含义+原因+排查步骤
   工具2：read_plc_status() —— 读状态字/故障码寄存器（demo阶段模拟数据）
   工具3：search_history() —— 查历史相似故障
   ↓
编程 Agent（第二能力）：输入IO表+设备清单 → 生成ST代码 → 语法校验
   ↓
界面：Web 对话式
```

## 五、为什么这个方向有市场

1. 中小非标设备厂：没MES、设备没联网、全靠老师傅——老师傅退休经验就断档
2. 非计划停机损失大（一条产线停一小时几万块）
3. 故障码手册是给懂电气的人看的，Agent 能把它变成"人话+定位+排查步骤"
